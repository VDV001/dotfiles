# Finance Log Skill

Логирует финансовые операции через движок kb-engine и пересобирает dashboard.

## Пути

- ledger (истина для транзакций): `~/claude-cowork/finances/transactions.jsonl`
- xlsx (витрина + балансы счетов): `~/claude-cowork/finances/Учёт_финансов.xlsx`
- build: `~/claude-cowork/knowledge-base/_tools/build_dashboard.py`

## Главное правило

**В xlsx НЕ писать напрямую — ничего.** Запись идёт в ledger через `kbengine fin add`,
затем `kbengine fin sync` переносит её в книгу с сохранением стилей и проставляет `id`.
Прямая запись openpyxl создаёт строку без `id`, движок видит расхождение,
и ledger отстаёт от книги до следующей ручной синхронизации (так уже случалось: 14 строк за 29-30.07).

**Исключения больше нет.** Балансы счетов до v0.12.0 приходилось писать openpyxl, потому
что движок их только читал; теперь есть `kbengine fin balance` (шаг 3в), и обход не нужен.

## Алгоритм

### 1. Определить тип(ы) операции

**Расход** — "потратил", "купил", "сходил", "заплатил", "расход", "минус X"
**Доход** — "получил", "зарплата", "стипендия", "пришло", "доход", "плюс X"
**Обновление баланса банка** — "на Альфе стало X", "на Сбере теперь X", "стало меньше на X"

Один запрос может содержать несколько операций (расход + обновление счёта).

### 2. Уточнить только если реально непонятно

Не спрашивать лишнего. Если из контекста понятно — действовать сразу.

Нужно для **расхода**: сумма, категория (угадать по контексту), место (если указано).
Нужно для **дохода**: сумма, источник.
Нужно для **счёта**: банк + новый баланс (или дельта).

### 3. Записать операцию

Пути короче держать в переменных:

```bash
LEDGER=~/claude-cowork/finances/transactions.jsonl
BOOK=~/claude-cowork/finances/Учёт_финансов.xlsx
```

#### 3а. Расход

```bash
kbengine fin add --ledger "$LEDGER" \
  --kind expense --date 2026-07-31 \
  --cat 'Еда' --sub 'Продукты' --place 'Магнит' \
  --amount '129,98' --account 'Сбербанк' --note 'описание, если есть'
```

**Счёт у расхода — это `--account`, а не `--source`.** Флаги значат разное:
`--account` — через какой счёт прошли деньги, `--source` — как запись получена
(«Чек», «Скрин банка»). Название счёта, поданное в `--source`, движок отвергает
при синхронизации: на листе «Счета» оно прочиталось бы обратно как счёт, и запись
разошлась бы сама с собой. Ошибка формулируется так:
`the source names a known account: … pass it as the account instead`.

`--amount` понимает и `129.98`, и `129,98`, и `1 500`. `--date` по умолчанию сегодня.
`--place`, `--note`, `--sub` опциональны. `id` движок генерирует сам.

#### 3б. Доход

То же самое с `--kind income`; **категории и счёта у дохода нет** — домен их не
принимает. Обязателен по смыслу `--source`, и здесь он значит именно источник денег
(«Зарплата», «Стипендия», «Перевод от мамы», «Кешбэк», «Альфа-Банк» для процента
на остаток) — в отличие от расхода, где источником называется способ фиксации.

```bash
kbengine fin add --ledger "$LEDGER" --kind income --date 2026-07-31 \
  --amount '90000' --source 'Зарплата' --note 'за июль'
```

#### 3в. Обновить баланс счёта (лист «Счета»)

```bash
kbengine fin balance --from "$BOOK" --bank 'Альфа-Банк' --amount '1447,12'
```

Счёт ищется **по имени**, а не по номеру строки. Банк, которого на листе нет,
отвергается с перечислением известных — не заводить его руками: этот лист
словарь, решающий, что считается счётом во всей остальной книге.

Дату движок ставит сам (сегодня, днём без времени) и сохраняет формат ячейки.

#### 3г. Завести новый счёт

```bash
kbengine fin balance --from "$BOOK" --bank 'Долг → Отец' --amount '3000' --create
```

`--create` — **отдельное намерение**, а не «запиши всё равно». Без него
незнакомое имя остаётся опечаткой, и это правильно. Спрашивать владельца перед
заведением: имя, которого нет на листе, чаще промашка в раскладке, чем новый
счёт.

Написание сверяет движок: «долг→отец» рядом с «Долг → Отец» — тот же счёт, и
второй строки не появится. Формат новой строки наследуется от соседней.

#### 3д. Долги: не расход и не доход, а счёт

Дал в долг — деньги не потрачены, они лежат у другого человека. Вернули — это не
доход. Поэтому в ledger не попадает **ничего**, меняются только балансы:

```bash
# дал 3000 отцу с Альфы
kbengine fin balance --from "$BOOK" --bank 'Альфа-Банк' --amount '<новый остаток>'
kbengine fin balance --from "$BOOK" --bank 'Долг → Отец' --amount '3000' --create

# вернул 1000 из 3000
kbengine fin balance --from "$BOOK" --bank 'Долг → Отец' --amount '2000'
kbengine fin balance --from "$BOOK" --bank 'Альфа-Банк' --amount '<новый остаток>'
```

Соглашение имён — **строка на должника**: «Долг → Отец», «Долг → Имя». Закрытый
долг остаётся строкой с нулём (как «Заморозка → Вклад»), удаляется руками, когда
список станет длинным. Стрелка не украшение: движок читает её как род счёта и
показывает долги отдельным подытогом, не смешивая с деньгами на карте.

Если команда отвечает `unknown fin subcommand "balance"` — установленный движок
старше v0.12.0. Обновить: `kbup`. **Не обходить это openpyxl'ом** — сказать
владельцу, что движок надо пересобрать.

Писать баланс openpyxl напрямую **больше не нужно и нельзя**: до v0.12.0
движок балансы только читал, и обход был вынужденным. Прямая запись мимо
движка — это второй писатель одного файла, а два писателя рано или поздно
расходятся в том, что в файле написано.

### 4. Синхронизировать книгу с ledger

```bash
kbengine fin sync --from "$BOOK" --ledger "$LEDGER"
```

Ожидаемый вывод — `ledger → workbook` с числом добавленных строк.
Если сомневаешься, что произойдёт, сначала `--dry-run`: он ничего не меняет.
Если вывод показал `modified` или `removed`, которых ты не делал — **остановись и покажи владельцу**,
это признак, что книгу правили ещё где-то.

### 5. Пересобрать dashboard

```bash
cd ~/claude-cowork/knowledge-base && ./.venv/bin/python _tools/build_dashboard.py
```

**Только через `./.venv/bin/python`.** Системный `python3` не видит openpyxl и молча собирает
дашборд с нулями вместо финансов вместо того, чтобы упасть.

### 6. Ответить кратко

> Записал: **Еда → Продукты · Магазин · 60 ₽** (29.03.2026)
> Альфа-Банк: 1 507,12 → **1 447,12 ₽** · Баланс: **1 788 ₽**

## Автоматическое определение категории

**Источник истины — `~/claude-cowork/finances/finance-aliases.json`.** Тот же файл
читает `kbengine tui` при быстром вводе. Открывать его перед разбором места, а не
угадывать по памяти: два справочника в течение месяца разложат одну «Живику» по
разным категориям, и разбивка по категориям тихо раздвоится.

```bash
jq -r '.places | to_entries[] | "\(.key) → \(.value.category) · \(.value.subcategory)"' \
  ~/claude-cowork/finances/finance-aliases.json | head -20
```

Ключи сравниваются без учёта регистра, «ё» и дефисов: `Т-Банк`, `т банк` и `тбанк` —
одно и то же. Места и написания счетов собраны из реальной истории трат; сколько их
сейчас — покажет команда выше, число здесь называть не нужно, оно разойдётся с файлом.

**Новое место, которого в словаре нет:** спросить владельца о категории, записать
трату и дописать слово в словарь — тогда со следующего раза его узнают обе
поверхности. Не угадывать молча.

Запасной ориентир, если словарь недоступен:

- магазин / продукты / пятёрочка / магнит / вкусвилл / лента → **Еда → Продукты**
- кафе / ресторан / кофе / поль бейкери → **Еда → Рестораны/кафе**
- доставка / самокат / яндекс еда → **Еда → Доставка еды**
- такси / яндекс такси / uber → **Транспорт → Такси**
- метро / автобус / трамвай → **Транспорт → Общественный**
- netflix / spotify / подписка → **Подписки → Сервисы**
- аптека / лекарства → **Здоровье → Аптека**
- одежда / обувь / zara / h&m → **Одежда → Одежда**
